# Защита проекта «Шляпа»

## Подготовка

Открыть Xcode → alias → iPhone Simulator. Сервер запустить командой `npm start` из папки Server. Убедиться, что `.env` содержит настоящий ключ Groq; ключ не показывать на экране. Проверить генерацию «Кухня» заранее. На физическом iPhone указать HTTPS-адрес сервера. Сохранить хотя бы один сгенерированный набор для демонстрации офлайн.

До добавления ключа честно показывать состояние «Генератор ещё не подключён»; не называть тестовые ответы реальной генерацией. Полный путь через Groq проверяется после подключения ключа.

## Демонстрация · 5–7 минут

1. **Главная и навигация.** Показать вкладки Играть / История / Правила. Начать игру. Объяснить: навигация реализована в SwiftUI через TabView и NavigationStack.
2. **UIKit.** Выбрать набор в одном столбце. Это UIViewController с UICollectionView и собственной PackCell, встроенный через UIViewControllerRepresentable. Выбор передаётся в общий AppViewModel.
3. **Сеть.** «Своя тема с ИИ» → «Кухня», 30 слов → создать. Дождаться ответа; удалить 1–2 слова, сохранить. Показать новый набор. Тема уходит через URLSession на наш Node-сервер, который вызывает Groq. Ключ находится только на сервере. Ответ JSON валидируется дважды.
4. **Настройки.** Команды «Лисички» и «Медведи», показать добавление третьей и удаление. Время 30 сек, общее слово 10 сек, цель 10 очков. Время меняется с шагом 10.
5. **Игровой ход.** Передать телефон → Мы готовы. Угадать свайпом вверх; пропустить свайпом вниз; вернуть последнее слово. Поставить паузу: таймер стоит. Продолжить. Во время ожидания сигнала коротко объяснить архитектуру.
6. **Общее слово.** После сигнала угадывают обе команды. Завершить слово → отдать очко другой команде. В итогах изменить одно слово и сохранить. Показать правильный счёт и следующую команду.
7. **Победа и исправления.** На следующем ходе открыть паузу → Завершить игру → подтвердить. Показать корону, счёт. Проверить слова → убрать/вернуть очко → сохранить; лидер пересчитывается.
8. **База.** Главная → История → открыть партию. Перезапустить приложение обычным Run (не UI-тестом): история и свой набор сохранились. Отключить интернет: встроенные/сохранённые наборы работают; новая генерация показывает ошибку без падения.

## Что показать в коде

- `Domain/GameDomain.swift`: правила подсчёта, общего слова, равного числа ходов и победы; структуры без зависимости от UI.
- `Presentation/AppViewModel.swift`: состояние и обработка действий, внедрение `GameRepository` / `WordGenerating`.
- `Data/Repositories.swift`: SwiftData и URLSession скрыты за отдельными протоколами. Экраны не создают ModelContext и URLSession.
- `Presentation/PacksViewController.swift`: UICollectionView + кастомная ячейка.
- `ContentView.swift`: TabView, NavigationStack и SwiftUI destinations.
- `Server/server.mjs`: строгая JSON Schema, проверка входа, таймаут, обработка 429/ошибок, ключ из переменных окружения.

## Ответы на вопросы

**Почему SwiftData с JSON?** Для небольшого учебного проекта хранится самодостаточный снимок партии и наборов. SwiftData отвечает за дисковое хранение, выборку и уникальность ключей. Ограничение: нельзя эффективно фильтровать слова внутри снимка предикатами БД; при большом объёме стоит выделить сущности Game/Team/WordResult.

**Почему не хранится общий счёт?** Он вычисляется из журнала слов. Исправление автоматически влияет на таблицу и победителя; нет двух расходящихся источников истины.

**Как соблюдён SOLID?** SRP — отдельные правила, хранилище, сеть и представление. DIP — ViewModel зависит от протоколов. ISP — контракты сети и хранения независимы. OCP — можно заменить генератор/хранилище. LSP — реализации сохраняют общий контракт, тестовые подстановки поддерживают результат и ошибку.

**Что осталось до публичного релиза?** Подключить и проверить реальный ключ, разместить сервер с HTTPS, добавить авторизацию и устойчивые лимиты. Расширить словарь, провести пользовательское тестирование и добавить миграции схемы перед изменением формата сохранений.
