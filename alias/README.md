# Шляпа · iOS

Игра на одном телефоне для 2–6 команд. SwiftUI + UIKit, SwiftData и генерация своих тем через сервер Groq. Минимальная версия iOS — 17. Для сборки нужен Xcode 16 или новее (проект проверяется в Xcode 26.2).

## Запуск

Откройте `../alias.xcodeproj`, выберите схему `alias` и iPhone Simulator, нажмите Run. Для запуска на физическом iPhone выберите свою команду подписи в Signing & Capabilities.

Встроенные 250 слов и фраз работают без сервера. «Рулетка» перемешивает встроенные наборы. Выбранные наборы объединяются без повторов; в пределах одной партии слово не повторяется. При исчерпании колоды игра завершается с текущим счётом.

## Генерация своих тем

1. Нужен Node.js 22+.
2. В `Server` скопируйте `.env.example` в `.env`.
3. Когда будет ключ, заполните только `GROQ_API_KEY` в `.env`. Модель задаётся переменной `GROQ_MODEL`; по умолчанию `openai/gpt-oss-20b`.
4. В папке `Server` выполните `npm start`.
5. В приложении: Играть → Начать игру → Своя тема с ИИ. В «Подключении к серверу» для симулятора укажите `http://localhost:8787`.
6. Введите тему, сложность и количество слов. Проверьте результат, удалите неподходящее и сохраните. Сохранённый набор доступен офлайн после перезапуска.

Ключ не помещается в iOS-приложение, UserDefaults, Git или презентацию. `.env` исключён из Git. Пока ключ не добавлен, сервер отвечает 503 с объяснением; приложение не выдаёт встроенные слова за результат ИИ.

На физическом устройстве localhost указывает на сам iPhone. Для генерации на iPhone разместите сервер за HTTPS и укажите его URL в приложении. Сервер запускается на loopback по умолчанию; для облака настройте HOST/PORT у провайдера. Перед публичным запуском нужны авторизация клиента и общий лимит запросов (текущий лимит — 6 запросов в минуту на IP в памяти одного процесса; за reverse proxy он может быть общим для всех клиентов). Не включайте платный тариф только ради защиты; бесплатные квоты и доступность модели зависят от аккаунта Groq.

## Архитектура

- **Domain**: value types и `GameSession`, правила ходов, очков и победы; не зависит от UI, сети и SwiftData.
- **Data**: `GameRepository` / `SwiftDataGameRepository`, модель `StoredDocument`; `WordGenerating` / `RemoteWordGenerator` с URLSession.
- **Presentation**: `AppViewModel` с внедрением зависимостей через протоколы; экраны получают только ViewModel / значения и действия.
- **Composition root**: `aliasApp` создаёт SwiftData-контейнер и реализации зависимостей.
- **Server**: небольшой Node HTTP-сервис без npm-зависимостей. Проверяет запрос, вызывает Groq со строгой JSON Schema, удаляет повторы и некорректные элементы. Ответ проверяется повторно на клиенте. Смысловое качество и соответствие теме проверяет игрок в предпросмотре.

SRP: правила игры, хранение, сеть и отображение разделены. OCP/DIP: источник генерации и хранилище заменяются реализациями протоколов без изменения экранов. ISP: отдельные контракты хранения и генерации. LSP: тестовые реализации используют тот же контракт, включая ошибки; наследования ради архитектуры нет.

## Экраны и требования

- SwiftUI `TabView`: Играть, История, Правила; в каждой вкладке — `NavigationStack`.
- UIKit `PacksViewController`: UICollectionView, собственная `PackCell`, compositional layout; интеграция через UIViewControllerRepresentable.
- SwiftUI: главная, команды, настройки, генератор, передача телефона, слово, общее слово, выбор команды, результаты хода, счёт, победа, пауза, история, проверка слов, правила.
- SwiftData: свои наборы, незаконченная игра, история завершённых игр. Запись на каждое игровое действие; при уходе в фон — пауза и сохранение оставшегося времени.
- URLSession: POST `/generate` → Node → Groq → JSON со словами.

## Правила и детали

Время хода 30–120 секунд с шагом 10. Общее слово: 10/20/30 секунд или без ограничения. Вверх — угадано, вниз — пропуск; области можно нажимать, доступны VoiceOver-действия. Отмена возвращает последнее слово. Пауза и уход в фон останавливают таймер. При восстановлении активный ход открывается на паузе.

Победа по целевому счёту проверяется после равного числа ходов. При равном счёте игра продолжается. Если слова закончились или игроки завершили игру вручную, определяется текущий лидер, возможна ничья. Очки вычисляются по журналу слов, а не хранятся отдельно: исправления после игры меняют победителя. За пропуск можно включить −1; незавершённое обычное слово без общего режима не получает штраф.

## Проверки

`Tests/run.sh` — проверка правил игры и дискового хранения SwiftData на macOS. `cd Server && npm test` — контракт генерации, ошибки, отсутствие ключа, валидация и лимиты; Groq в этих тестах заменён управляемым тестовым ответом. Реальную генерацию Groq необходимо проверить после добавления ключа.
